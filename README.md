# 올팍 플랜B

올림픽공원 공연장을 갑자기 못 쓰게 됐을 때, 옮겨 갈 공연장을 실측 3D 모델 위에서 배치해 보고 몇 명까지 받을 수 있는지 기준별로 확인하는 웹 도구입니다.
2026 한국체육산업개발 공공데이터 활용 경진대회 출품작입니다.

- 배포 주소: (Vercel 연결 후 기입)
- 배치한 내용은 주소 뒤 `#p=...`에 압축돼 들어갑니다. 링크만 보내면 같은 배치가 그대로 열립니다.

## 할 수 있는 것

| 기능 | 내용 |
|---|---|
| 대체 공연장 찾기 | 원래 공연장, 날짜, 관객 수를 넣으면 그 기간에 공개 일정이 없는 공연장을 위로 올려 보여 줍니다. |
| 3D 배치 | 기관이 공개한 공연장 3D 모델 위에 무대(엔드·센터·돌출), 스탠딩·좌석·제외 구역, 출구를 놓습니다. 지붕을 잘라 안을 보거나 위에서 내려다볼 수 있습니다. |
| 수용 인원 확인 | 그린 구역의 순면적으로 기준별 인원과 밀집 단계를 계산하고, 출구 규정과 비교합니다. 옥외에서 1천 명 이상이면 재해대처계획 신고 안내를 띄웁니다. |
| 검토서 | 3D 화면 캡처, 계산표, 출처를 한 장으로 모아 인쇄하거나 PDF로 저장합니다. |
| 주차 현황 | 상단에 올림픽공원 주차장 현재 주차 대수를 1분마다 갱신해 보여 줍니다. |

처음 열면 나오는 안내창과 왼쪽 위 "예시로 둘러보기"에서 미리 만든 배치 두 개(KSPO DOME 플로어 스탠딩, 88잔디마당 노천무대 앞 잔디)를 바로 불러올 수 있습니다.

## 계산 기준

숫자는 모두 `src/data/standards.ts`에 출처와 함께 모아 두었습니다. 숫자를 바꾸거나 더할 때는 출처도 같이 적습니다.

| 항목 | 값 | 출처 |
|---|---|---|
| 권장 할당 | 서서 보는 관람 1인당 0.46㎡ | 행정안전부 「다중운집인파사고 안전관리 가이드라인」(2024.9) p.2 |
| 밀집 단계 | 여유 1㎡당 2명 이하, 주의 3~4명, 위험 5명 이상 | 같은 가이드라인 p.16 |
| 소방 수용인원 산정식 | 바닥면적 ÷ 4.6㎡ (고정 의자는 의자 수) | 「소방시설 설치 및 관리에 관한 법률 시행령」 별표 7 |
| 관람실 출구 | 바닥면적 300㎡ 이상이면 2곳 이상, 각 1.5m 이상, 합계는 100㎡마다 0.6m 이상 | 「건축물의 피난·방화구조 등의 기준에 관한 규칙」 제10조제2항 |
| 재해대처계획 | 공연장 외 장소에서 1천 명 이상이면 14일 전까지 신고 (변경은 7일 전) | 「공연법」, 공연안전지원센터 체크리스트 |

- 가이드라인 단계 사이 값(1㎡당 2명 초과 3명 미만, 4명 초과 5명 미만)은 더 높은 단계로 봅니다.
- 소방 산정식은 소방시설 설치 기준을 정할 때 쓰는 식이라 공연 인원 상한과는 성격이 다릅니다. 화면에도 그렇게 적어 두었습니다.
- 모든 계산은 검토용 참고값입니다. 실제 수용 인원은 공연장 운영자의 재해대처계획과 관할 기관 판단을 따릅니다.

## 실행

Node 18 이상.

```bash
npm ci
npm run dev        # 개발 서버
npm run typecheck  # 타입 검사
npm run build      # dist/ 생성
npm run preview    # 빌드 결과 확인
```

브라우저는 WebGL이 켜져 있어야 합니다.

## 배포 (Vercel)

1. Vercel에서 이 저장소를 Import 합니다.
2. Framework Preset은 Vite, Build Command `npm run build`, Output Directory `dist` (자동으로 잡힙니다).
3. 지금은 환경변수가 필요 없습니다. 일정 API를 붙일 때 키를 추가합니다(아래).

모델 다섯 개가 합쳐 약 31MB라 첫 로딩에 시간이 걸릴 수 있습니다. 모델은 공연장을 고를 때 하나씩 받습니다.

## 일정 데이터

지금은 올림픽공원 공식 홈페이지의 공연·행사 일정을 받아 둔 스냅샷(`public/data/events.json`)을 씁니다.

```bash
npm run data:events                   # 2개월 전 ~ 6개월 뒤
npm run data:events -- 202601 202703  # 기간 지정
```

갱신한 뒤에는 `src/lib/events.ts`의 `EVENTS_SOURCE.collectedAt` 날짜를 바꿉니다. 공개된 일정 기준이라 실제 대관 가능 여부는 대관 담당 확인이 필요하고, 취소된 공연이 목록에 남아 있을 수 있습니다.

### 공공데이터 API로 바꾸는 순서

1. 2026-11-22 18:00 점검이 끝나면 공공데이터포털에서 '올림픽공원 공연정보', '대관정보'의 바로가기로 들어가 문화공공데이터광장에서 활용신청하고 인증키를 받습니다.
2. `api/events.ts` 서버리스 함수를 추가합니다. 환경변수의 키로 API를 부르고, 응답을 앱의 `ParkEvent` 형식(`id, title, begin, end, venue, venueCode, time`)으로 바꿔 돌려줍니다. 키가 브라우저에 노출되지 않습니다.
3. `src/lib/events.ts`의 `loadEvents()`가 `/api/events`를 먼저 부르고, 실패하면 지금의 스냅샷을 쓰도록 바꿉니다.
4. Vercel 프로젝트 Settings → Environment Variables에 키를 넣고 다시 배포합니다.

## 3D 모델을 만든 과정

원본은 공공데이터포털 15127487의 첨부 파일입니다 (`88_glb.zip`, `lake_glb.zip`, `skhandball_glb.zip`, `woori_glb.zip`, `kspodome_dae.zip`). 변환에는 gltf-transform CLI v4를 썼습니다.

GLB로 받은 네 곳(88잔디마당, 수변무대, 핸드볼경기장, 우리금융아트홀):

```bash
gltf-transform metalrough in.glb mr.glb
gltf-transform optimize mr.glb out.glb --compress meshopt --texture-compress webp --texture-size 1024
```

KSPO DOME은 SketchUp DAE라서 한 단계가 더 있습니다.

1. COLLADA2GLTF 2.1.5로 GLB 변환 (경로에 `#`가 있으면 실패해서 폴더 이름을 바꿈)
2. `tools/model/strip-far-nodes.mjs`로 바닥 바깥에 떨어져 있는 방위 글자(N·E·S·W) 메시 4개 제거
3. 위와 같은 `optimize` 명령

축척은 공식 제원과 맞춰 봤습니다. KSPO DOME은 모델의 건물 외곽 지름이 약 131.5m로, 건축면적 14,016㎡를 원으로 본 지름(약 133.6m)과 비슷합니다. 핸드볼경기장은 모델 폭이 약 106m이고, 건축면적 9,077.99㎡를 원으로 본 지름은 약 107.5m입니다.

88잔디마당 모델은 가로 약 88m, 세로 약 83m 범위만 담고 있어 잔디마당 전체(약 33,000㎡)보다 작습니다. 화면에도 이 점을 적어 두었습니다.
